## 2. 需求 14：双击只选中（D1，已交付）

编辑模式下双击命中可编辑图元时，只把该图元单独选中——组内成员只选成员本身，不展开组树；不再发属性请求、不弹窗。锁定或隐藏图层仍给“先解锁”提示。查看 / 画笔 / 文字模式双击不再弹窗。

属性窗保留三个入口：编辑菜单“图元属性…”、编辑面板属性按钮、编辑模式右键菜单。

代码落点：

- `CanvasView::mouseDoubleClickEvent`：`clearSelection()` 后 `setSelected(true)`，不再 `emit itemPropertiesRequested`。
- 删除只服务旧路径的 `CanvasViewHitTester::PropertyItemAt`。
- 同步 README、编辑模式 tooltip（`UiActionFactory`、`ViewStatusController`）与中文翻译条目。
- 自检改成“双击不请求、只单选”，`MainWindowFlowTests` 补“菜单入口仍能打开属性窗”。

影响：需求 42 的“任意模式只读属性窗”不再有双击入口；要保留得单开一条“非编辑模式右键只读入口”。

## 3. 需求 15：F11 全屏

### 3.1 状态机与可见面（F1，已交付）

- `FullScreenController` 读 `isFullScreen()` 单一真相；进入时快照菜单栏、状态栏、主工具栏、模式卡的可见性与窗口几何、最大化状态。
- 进入时先挡模态窗（`QApplication::activeModalWidget()` 非空直接返回）、`FinishCurrentStroke()` 收笔，再隐藏四类界面后 `showFullScreen()`。
- 退出按快照还原；`showNormal()` 只在不处于全屏时调用，避免二次触发 `changeEvent`。
- `MainWindow::changeEvent` + `HandleWindowStateChange` 兜底：被窗口管理器踢出全屏时只还原界面。
- `closeEvent` 依次：收笔 → `MaybeSave()` → `ExitIfActive()` → 落盘，避免把全屏几何写进设置。
- 全屏只剩四项：画布、顶部悬浮工具栏、编辑面板、图层面板（后两者的悬浮形态属 F3）。

### 3.2 悬浮工具栏（F2，已交付）

固定单行、顶部水平居中，`top = max(32, 标题栏高 + 8)`；卡片高 58，图标 26px，窗口缩放时 `resizeEvent` 重新居中并 `raise()`。

| 编号 | 目标 | 复用动作 |
| --- | --- | --- |
| 0 | 椭圆 | `ShapeAction_ellipse` |
| 1 | 直线 | `ShapeAction_line` |
| 2 | 直线箭头 | `ShapePreset_lineArrow` |
| 3 | 三角形 | `ShapeAction_triangle` |
| 4 | 圆角矩形（需求写作“圆形矩形”） | `ShapePreset_roundedRect` |
| 5 | 五角星 | `ShapeAction_star` |
| 6 | 菱形 | `ShapeAction_diamond` |
| 7 | 心形 | `ShapeAction_heart` |
| 8 | 左括号 | `ShapePreset_braceLeft` |
| 9 | 自定义图形按钮 | `m_customShapeMenu` |

其后是填充样式、填充色、描线样式、描线色、描线宽度（74×30，与主工具栏双向同步），最右是模式徽标（显示当前模式快捷键字符，点开就是模式菜单，随 `modeChanged` 刷新）。

口径：

- 全量 27 个图形方案已否决（两行会压掉画布上沿），其余图形仍从主工具栏 / 插入菜单取用。
- 平滑容差不进栏（只作用于画笔拟合，不影响已有图元）。
- 按钮点击统一 `action->trigger()`，不使用 `setDefaultAction`（会被 action 的 16px 图标覆盖 26px）。
- 键位字符与数字键一一对应（见 3.3），全屏外按下数字键不触发。

### 3.3 快捷键保活与数字键（均已交付）

- 实测（Qt 6.8.3 离屏探针）：菜单栏或工具栏隐藏后，挂在它们上面的 `QAction` 快捷键静默失效；把同一动作再 `addAction` 到可见的中心控件即可恢复，两处同时注册只触发一次；输入框聚焦时数字键进输入框。
- 现实现：进入全屏时把菜单（递归子菜单）、工具栏、模式组里带键位的动作挂到画布视图，退出只摘掉自己加过的；F11 本身也在其中，所以全屏后退得出来。
- 数字键：`MainWindow` 装自身为事件过滤器，焦点控件没消费的 `KeyPress` 冒泡到窗口后交给 `FullScreenController::HandleKeyPress`，只认无修饰的 `0`–`9`，命中即 `FullScreenBar::TriggerDigit` 点按钮（9 是自定义图形菜单）；走的是“未处理的冒泡事件”，所以描线宽度等输入框聚焦时数字照常进输入框，不进改键表。
- 自检覆盖：F11 绑定与保活、9 个按钮、居中与顶部留白、数字键落点、输入框让位、面板悬浮与还原，共 4 段。

### 3.4 全屏期面板布局（F3，已交付）

- 进入全屏后把编辑面板与图层卡 `setFloating(true)`：编辑面板贴左侧、顶部让开悬浮工具栏（96px），宽度沿用 260–360 区间、高度吃到窗口底部前 16px；图层卡 280×260 贴右下角（16px 外边距）。
- 编辑面板沿用既有规则“悬浮即随选中显隐”：有选中出现、清空选中隐藏；图层卡常驻。
- 退出（含被窗口管理器踢出全屏的兜底路径）按进入前的快照还原：停靠侧、悬浮几何、可见性、右侧上下切分与高度；`SetFloating(false)` 后再 `addDockWidget` 并重排，不调用 `ApplyDockLayout`（那里每次都会重复 `connect`）。
- 全屏期 `m_applyingDockLayout` 与 `m_fullScreenLayout` 双闸门，`RememberPropertiesPanelDockState` / `RememberDockOrder` / 延迟保存定时器 / 移动事件都不落盘，避免把全屏几何写成用户布局。
- 实机（Windows 2560×1440）F11 截图确认：悬浮图层卡确实压在满屏画布之上，右/下边距约 16px，无被裁切。

### 3.5 平台风险

`QDockWidget` 悬浮形态能否稳定盖在全屏窗口之上属窗口管理器行为，离屏自检证明不了。Windows 已实机验证通过；Linux(X11) 仍待验一次，若被盖住先加置顶标志，仍不行改走“画布内浮层卡片”。

### 8.1 那 6 条失败是测试自己的坐标 bug，不是产品回归

定位过程：先加一条临时断言把命中现场打出来（`rect=774,449 128x128 zoom=0.218 click=187,291 sel=1 type=CurveItem`），看到三处问题叠在一起：

1. 画笔曲线的手工抖动是按**视图像素**写死的（±10 / ±12 px），而当时适配缩放只有 0.218，等于曲线在场景里上下摆动 ±50 个单位，直接糊到矩形上沿；点矩形左上角 12 个场景单位（≈2.6 px）必然先被曲线抢走。改成按场景坐标换算抖动。
2. Ctrl 点选曲线的位置是“按几何估算”的，而 `CurveItem::StrokePoints()` 返回的是**图元本地坐标**，原先直接当场景坐标用，点必然落空，于是加选失败、`LineSplitOps::Supports` 跟着为假。改成 `curveItem->mapToScene(...)` 取真实采样点。
3. 另外该段若插过图形，`window.close()` 会触发保存询问，离屏下模态窗卡死，自检看门狗按“超时退出码 3”收场、报告只写到一半；收尾补 `FinishCurrentStroke()` + 切回查看模式 + `UndoStack()->setClean()`。

结论：产品路径（点击命中优先级、Ctrl 加选、分割判定）没问题，不用改代码，只修测试。

### 8.2 公共属性分派并入描述符

`CanvasItem::PropertyValue` / `SetPropertyValue` 原来的两个 `switch`（名称 / 图层 / 层内高度 / 位置 / 尺寸 / 旋转 / 中心点 / 不透明度）已删除，统一改成查 `ItemPropertyCatalog::Find` 的 reader / writer。核对过 30 条描述与 29 个 `case` 标签一一对应、无遗漏，公共属性这一层不再有两套分派。各图元子类里**按类型**的属性分派（填充、描线、长半轴、正弦参数、文字样式等）保留——它们不是公共属性，且各自带有类型特化逻辑（弧线的长短半轴走 `EllipseSize`、椭圆的走 `EllipseAxis`），并入描述符要逐项验证等价，留作后续单独一批。
